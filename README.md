# Tendências em Ciência da Computação — Plano de Aulas (modelo 5W2H)

Resumo
-----
Este repositório reúne materiais, atividades e projetos para o curso / módulo "Tendências em Ciência da Computação", organizado no formato 5W2H para facilitar planejamento, execução e avaliação conforme os objetivos do plano de aulas.

5W2H
----
- O Que (What)
  - Conteúdo: pesquisa e estudo de temas emergentes em Computação (ex.: IA explicável, segurança aplicada, computação quântica, computação pervasiva, privacidade, MLOps, edge computing).
  - Atividades: leituras guiadas, seminários, estudos de caso, workshops práticos, desenvolvimento de mini-projetos e apresentação final.
  - Produtos: slides, relatórios, código-fonte dos projetos, notebooks, rubricas de avaliação.

- Por Que (Why)
  - Objetivo pedagógico: contextualizar os alunos nas direções atuais da área, desenvolver capacidade crítica para avaliação de tecnologias emergentes, fomentar habilidades práticas de pesquisa, desenvolvimento e comunicação científica.
  - Competências esperadas: análise crítica, experimentação, trabalho em equipe, comunicação técnica e aplicação prática de ferramentas modernas.

- Quem (Who)
  - Público-alvo: estudantes de graduação/pos-graduação em Ciência da Computação e áreas afins.
  - Papéis:
    - Coordenador/Professor: define temas, avalia entregas, orienta projetos.
    - Monitores/Mentores: apoio técnico e de conteúdo.
    - Alunos/Times: desenvolvimento das atividades e projetos.
    - Colaboradores externos: convidados para seminários ou mentoria.
  - Contato: (inserir e-mail/Slack/Teams do docente).

- Onde (Where)
  - Ambiente de ensino: aulas presenciais e/ou remotas.
  - Repositório central: este GitHub para versionamento de materiais e submissão de projetos.
  - Plataformas complementares: repositórios individuais dos grupos, notebooks executados em serviços de nuvem/lab da instituição.

- Quando (When)
  - Duração sugerida: 10–14 semanas (ex.: um semestre).
  - Marcos principais:
    - Semana 1–2: introdução, definição de temas e formação de grupos.
    - Semana 3–6: leituras, seminários e prototipagem inicial.
    - Semana 7–10: desenvolvimento de projeto e validação.
    - Semana 11–12: entrega final, apresentações e avaliação.
  - Datas: ajustar conforme calendário acadêmico.

- Como (How)
  - Metodologia: combinação de aulas expositivas, estudos dirigidos, aprendizagem baseada em projetos (PBL) e avaliação formativa.
  - Fluxo de trabalho no repositório:
    1. Fork -> branch por grupo -> commits frequentes -> Pull Request para submissão final.
    2. Issues para rastrear tarefas; templates para relatório e PR.
    3. Uso de CI (opcional) para validar notebooks / build.
  - Avaliação:
    - Entregáveis (peso ex.): relatório técnico (30%), protótipo/código (35%), apresentação (20%), participação e atividades (15%).
    - Rubricas com critérios: clareza do problema, fundamentação teórica, método, resultados/validação, qualidade do código e comunicação.

- Quanto (How Much / Quanto custa / Esforço)
  - Esforço estimado: 8–12 h/semana por grupo durante o período de desenvolvimento.
  - Recursos materiais: computadores com acesso à internet; para experimentos avançados, contas em serviços de nuvem (opcional).
  - Custos diretos: idealmente zero (uso de software open-source); caso seja necessário, indicar custos de serviços em nuvem ou licenças.

Objetivos do Plano de Aulas (mapa rápido)
---------------------------------------
- Compreender e avaliar criticamente pelo menos 3 tendências tecnológicas.
- Aplicar ferramentas e técnicas para prototipar uma solução relacionada a uma tendência.
- Produzir um relatório e apresentação que demonstrem pensamento crítico e validação experimental.
(Observação: insira aqui os objetivos específicos do seu plano de aulas para alinhar rubricas e cronograma.)

Entregáveis e templates
-----------------------
- Template de relatório: /templates/relatorio.md
- Template de apresentação: /templates/apresentacao.pptx (ou .md)
- Template de PR/Issue: /templates/ISSUE_TEMPLATE.md, /templates/PULL_REQUEST_TEMPLATE.md

Como contribuir
---------------
1. Fork deste repositório.
2. Crie uma branch: git checkout -b feature/nome-do-grupo
3. Adicione materiais na pasta /atividades/ ou /projetos/grupo-x/
4. Abra uma Pull Request descrevendo alterações e entregáveis.
5. Use Issues para dúvidas e trackers de progresso.
